# 05 剧情叙事与台词

## 解决什么问题

把故事落成可制作、可配音、可本地化、可分支实现的工程文档：剧情大纲、章节 beat、角色弧光、过场需求、**台词脚本（带编号、情绪、镜头、多语种字段、配音指引）**、对话树。编剧、动画、音频、程序共用同一份文件。

## 何时写

概念期定主线大纲；垂直切片写 1 段过场+1 段分支对话的样板（含配音单流程）；量产前全章节 beat 锁定。

## 核心文档章节

### 1. 故事主干

- 一句话故事（主角/处境/目标/阻碍/代价）；主题（一句话，不喊口号，写成可检验的选择题）。
- 三幕（或对应类型结构）大纲：每幕的触发事件、转折、情感落点、时长占比。
- 结局设计：结局数、分歧点、前置条件；每个结局的情绪与信息揭示。
- **叙事配额**：过场总时长占比建议（动作类 ≤10%，恐怖/叙事类可 15-25%），避免「半小时不能操作」。

### 2. 章节 beat 表

| beat# | 章节 | 时长 | 场景 | 发生什么（动作+揭示） | 玩家获得的信息 | 情绪 | 文档/过场/对话编号 |
|---|---|---|---|---|---|---|---|

要求：每个 beat 都有「信息增量」（剧情或玩法信息），连续两个无增量 beat 必须合并。

### 3. 角色弧光

每个角色：欲望（want）/需求（need）/谎言（他相信的错误信念）/真相/弧光转折点（对应哪个 beat）。引用角色单页编号。

### 4. 叙事手法分配（别全靠过场）

3A 叙事配比表：过场（哪几处，为什么必须不可操作）、环境叙事（引用场景单页的叙事道具）、可拾取文档/录音（编号+全文）、无线电/同伴语音（实时伴随）、NPC 行为、加载页文本。每段信息指定**唯一主要载体**，避免重复。

### 5. 过场（Cutscene）需求

每条过场一张表：编号、触发条件、时长、是否可跳过、是否可暂停、进入/退出时玩家状态与位置（**退出位置必须与玩法衔接，杜绝过场后传送**）、参与角色、场景、镜头表（shot list）。

镜头表逐镜：镜号、景别（远/全/中/近/特写）、机位运动、时长（秒）、画面内容、台词编号、音效/音乐编号。程序/动画凭此可直接做分镜 animatic。

## 台词脚本格式（台词单页 dialogue-sheet）

**每条台词有全局唯一 ID**（如 `DL_01_L012`），配音、字幕、本地化、脚本全部用 ID 关联，**禁止把台词文本写死在代码或关卡触发器里**。

### 1. 元信息

对话编号、所属 beat/场景、触发条件（进入区域/拾取/完成事件）、参与角色、对话期间玩家状态（锁定/可走动/过场）、中断规则（被发现时是否打断）。

### 2. 台词表（标准列）

| ID | 说话人 | 中文台词 | 语气/情绪 | 表演动作/表情 | 镜头/站位 | 触发与等待 | 时长(s) | EN（英文） | 备注 |
|---|---|---|---|---|---|---|---|---|---|

填写规则：
- **语气**用可表演的词：压低声、颤抖、强装镇定、喘气中——禁止写「悲伤地」这种空泛词，要给演员具体动作。
- **触发与等待**：等玩家走近/等关门音效后/和上一句重叠 0.3s。
- 带停顿、重音用统一标注：`…`（停顿）、`【粗：你给我站住】`（重音）、`（喘气）`（表演提示）。
- 时长逐句估算（中文约 4-5 字/秒，英文约 2.5-3 词/秒），配音后回填实测时长。
- 台词长度硬上限：单条字幕 ≤ 2 行 × 每行约 18-20 个汉字；语音播放给玩家留阅读时间。

### 3. 分支对话树（如有）

用 Mermaid 画节点图，每个节点标 ID、说话人、选项文本、条件（属性/道具/剧情 flag）、后果（好感/信息/解锁）。规则：
- 选项风格写进文档：是否有时间限制、是否显示后果、可否全收集（玩家厌恶错过内容，重要信息要可补）。
- 分支必须收敛：画清每个分支从哪里重新汇合，避免内容无限膨胀。
- 玩家沉默选项（走人）必须设计。

### 4. 配音（VO）交接

- 从台词表生成配音单：ID、角色、语种、试音音色要求、情绪、时长、是否有死亡/受伤等非语义语音（grunt 表）。
- 非语义语音清单：受击、死亡、发力、惊吓、喘息——逐类列数量。
- 技术要求：48kHz、单句一文件、命名 `VO_角色_场景_序号.wav`（与 10 音频文档一致）。

### 5. 本地化规则

- 所有文本外部化到字符串表（key = 台词 ID）；文本不烘焙进贴图。
- 中文写作时预留英文/其他语种扩展：UI 文本德/俄文比英文长 30-50%，字段预留。
- 敬语/性别/单复数/语序差异（日语敬语、欧洲语言阴阳性）在变量拼接处提前标记，禁止运行时拼句子。
- 字幕规范：双语字幕策略、说话人颜色（可选）、字号与安全区（引用 06）、字幕背景可读性。

## 台词好坏示例

- 坏：「医生：我很害怕，这里很危险。」（直说情绪，无表演空间，玩家无法相信）
- 好：`DL_01_L012｜医生（盯着门缝，声音压到只有气声）：「别开灯。……它听见光，你懂吗？它听得见光。」（后退半步，手按在听诊器上）`——展示恐惧、埋下规则（声音机制）、塑造人物（不合逻辑的话暗示其精神状态）。

## 完成定义

- [ ] 故事主干含主题与可检验的道德/选择；结局条件明确
- [ ] 章节 beat 表每 beat 有信息增量，过场占比在配额内
- [ ] 每个角色有 want/need/谎言/真相与弧光转折
- [ ] 过场有镜头表，进入/退出位置与玩法衔接
- [ ] 每条台词有唯一 ID、语气可表演、时长估算、字幕长度合规
- [ ] 分支树收敛且玩家可回看关键信息
- [ ] 配音单、非语义语音清单、文件命名规范齐全
- [ ] 文本全部外部化，本地化字段与变量拼接规则就绪
