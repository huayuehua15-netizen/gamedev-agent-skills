# 09 动画规格（3D 骨骼动画 + 2D 帧动画）

## 解决什么问题

让动画师、程序（状态机）、特效、音频共用同一份动画规格：每条动画一个编号、统一时长帧率与事件埋点；同时覆盖 3D 骨骼动画、过场动画与 2D 帧动画（sprite 序列帧）。

## 何时写

垂直切片期锁定 locomotion 与 1 个攻击/受击全流程样板；量产期逐资产出单页。需与 04 玩法帧数据、06 交互、07 角色动作集对齐。

## 一、3D 动画全局规范

### 1. 基础规格

- 采样率 60fps（与战斗帧数据一致，帧率与帧数双写：`0.13s = 8 帧@60fps`）；移动类循环动画周期与位移按米/秒标定。
- 单位与轴向按引擎；骨骼命名统一（`Hips/Spine/Neck/Head/L_UpperArm/...`），面朝前向与建模规范一致。
- Rig：人形统一骨骼层级（主角/敌人/ NPC 可重定向）；手指骨骼、面部 blendshape 按角色等级（见 07）。
- 动画源文件 `.blend/.max/.ma` 归档，导出 `.fbx`（引擎导入），命名 `AN_角色_动作_序号`（`AN_Player_HeavyAttack_01`）。

### 2. 动画状态机（每角色必画，Mermaid）

以玩家为例必须覆盖：

- **Locomotion**：Idle（待机变体，3-8s 周期切换）→ Crouch/Walk/Run（2D blendspace，速度+方向）→ Sprint；转身（原地转身/移动转身）、起跳/落地（按高度分级）、停步（按速度分级）。
- **动作状态**：攻击（轻/重/连段，含连击窗口与取消窗口）、交互（按对象类型分层）、回避/格挡、受击（按方向/轻重）、死亡（按死因，至少 2-3 套）、复活/重生。
- **叠加与覆盖**：上半身层（持枪瞄准/持物）覆盖下半身移动；受伤叠加层、呼吸/颤抖叠加；过场与玩法状态的切换规则。
- 每个状态写：进入条件、退出条件、可被什么中断、过渡时长（秒，通常 0.1-0.25s，攻击被打断用 0.05-0.1s）。

### 3. 动作动画三段式（必须标注帧区间）

每条动作动画拆为：

1. **预备（Anticipation）**：告诉玩家要发生什么；攻击前摇帧数 = 04 战斗表的前摇。
2. **发生（Action）**：判定帧区间（起讫帧）、特效与音效事件、最大发力姿态。
3. **余响（Follow-through）**：恢复与可取消窗口；可取消窗口帧号与 04 连段表一致。

### 4. 动画事件（Animation Events，逐帧埋点）

每条动画必须列出全部事件帧：

| 事件类型 | 示例 | 用途 |
|---|---|---|
| 判定开关 | `HitboxOn f24` / `HitboxOff f30` | 与战斗判定严格对齐 |
| 脚步 | `FootstepL f12 (surface)` | 脚步声/贴花/扬尘，按表面材质 |
| 音效 | `Whoosh f22` / `Impact f28` | 引用 AU_ 编号 |
| 特效 | `DustParticle f12` | 引用 VFX 挂点 |
| 相机/震屏 | `CamShake f28 amp 0.6` | 反馈手感 |
| 根运动 | `RootMotion f10-f30` | 位移由动画驱动 |
| 命中停顿 | `HitStop 5f@28` | 冻结帧（与04一致） |

### 5. 根运动（Root Motion）与移动

- 明确哪些动作使用根运动（重攻击/处决/翻越/跳窗），哪些用代码位移（普通移动）。
- 翻越/攀爬：标注接触点（手、脚 IK 目标）、阶段（接近→挂边→翻越），与关卡可翻越高度（cm）匹配。
- 循环移动动画：每周期位移必须与代码速度匹配，避免滑步；提供原地与带位移两版（视引擎方案）。

### 6. 融合与手感

- 混合：Blendspace 轴（速度/方向/坡度）、转身惯性、上下坡脚步 IK、视线偏移与头部跟踪。
- 缓冲：输入缓冲（150ms）、连招窗口、跳跃土狼时间（100ms），与 04/06 数值一致。
- 脚步 IK 与贴地：不平地面的脚步修正、悬空腿部。
- 死亡与布娃娃：死亡动画→布娃娃的切换时机、布娃娃关节参数、尸体保留时间。

### 7. 面部与表演

- 面部 blendshape 集（写实 ≥52 ARKit 基）；表情库与情绪（至少 10 种核心表情）。
- 对话表演：音素（viseme）或管线（音频→面部）；眨眼、注视、头部微动（look-at）；对话中身体微动作（重心移动、手势）。
- 过场中面部与口型误差要求：口型与语音同步误差 ≤2 帧（约 33ms）。

### 8. 过场动画（Cutscene / 演出）

- 每个镜头一张镜头表（见 05 第 5 节）：景别、机位、时长、运动、动画、台词、音效。
- 动画师交付：分镜 animatic（低精度预演）→ 镜头动画→面部；标注进入/退出与玩法衔接的姿态、相机切换。
- 可跳过：跳过点（skip point）后玩家状态与位置必须与播完一致。

### 9. 动画单页（animation-sheet）内容

编号、角色、动作名、所属状态机位置、目的、帧区间表（预备/判定/余响/可取消）、事件表、根运动/位移数据、过渡规则、音频/特效/相机引用、导出设置、验收用例。

## 二、2D 帧动画（序列帧 / Sprite）规范

游戏包含 2D 元素（UI 小动画、广告牌画面、贴图屏幕、过场手绘、2D 小游戏）时使用。

### 1. 帧率与张数

- 常见帧率：12fps（风格化/省量）、15fps（手绘感）、24fps（高流畅）。循环动作优先用 12 或 15 的整除关系，避免抽帧不均。
- 张数预算：行走循环 6-8 帧/方向，跑 4-6 帧，攻击 6-10 帧，受击 2-4 帧，死亡 8-16 帧。单条动画张数在单页写明。
- 一拍二/一拍三规则：哪些帧重复（关键帧必画，过渡帧可省）。

### 2. 方向与分辨率

- 方向数：1/4/8 方向逐角色定（3D 渲染转 2D 时逐方向导出）；角色朝向翻转规则（左右镜像时注意不对称装备要重绘）。
- 单帧分辨率：基于游戏内最大显示尺寸的 2×（如最大显示 256×256 则按 512 出）；统一 PPU（像素/单位）与像素密度，避免角色大小不一。
- 像素风规则：固定调色板（列色板）、禁子像素、禁旋转缩放（或统一倍数）、描边宽度统一。

### 3. 图集（Sprite Sheet）与命名

- 打包图集：等大格（cell 尺寸）、固定 padding（防采样溢出）、按 2 的幂尺寸；记录图集元数据（JSON/数据行：帧名、坐标、尺寸、枢轴、时长）。
- 命名：`SP_角色_动作_方向_帧序号`（`SP_Nurse_Walk_E_03`）；图集 `T_SP_角色_动作集_帧数`。
- 枢轴：逐角色统一（脚底中心或引擎默认），避免切换动作时跳动。

### 4. 序列帧单页内容

动作、帧率、总张数与每帧时长、方向数、单帧尺寸与色板、图集布局、循环方式（循环/单次/往返）、事件帧（第 N 帧出判定/音效）、与 3D 或 UI 的合成方式。

## 三、完成定义

- [ ] 每个角色状态机覆盖 locomotion/动作/受击/死亡/交互，过渡时长给值
- [ ] 每条动画三段式帧区间与 04 战斗表完全一致
- [ ] 事件表逐帧列齐（判定、脚步、音效、特效、相机、根运动、hitstop）
- [ ] 无滑步（循环位移与速度匹配）；脚步 IK/贴地方案明确
- [ ] 面部：口型同步 ≤2 帧，表情/注视/微动作达标
- [ ] 过场有镜头表、animatic、跳过点状态一致
- [ ] 2D：帧率/张数/方向/分辨率/色板/图集/枢轴/事件帧齐全
