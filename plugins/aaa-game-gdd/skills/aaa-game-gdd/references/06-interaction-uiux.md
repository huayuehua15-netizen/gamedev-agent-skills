# 06 交互设计与 UI/UX

## 解决什么问题

定义玩家「能做什么动作、怎么操作、得到什么反馈、看到什么界面」。这是玩家对游戏的第一印象来源——3A 与业余作品的差距最直观地体现在操作手感与 UI 完成度上。

## 何时写

垂直切片期必须锁定操作方案与 HUD 主视觉；菜单与系统界面随系统文档推进；所有 UI 必须在 Beta 前全部可用。

## 一、交互设计

### 1. 玩家动词表（Verb List）

穷举玩家所有动作，每个动词一行：

| 动词 | 键鼠（默认） | 手柄（默认） | 上下文 | 进入/退出条件 | 关联系统/动画 |
|---|---|---|---|---|---|
| 屏息 | Ctrl | B/RT | 有敌人且玩家静止 | 按住/松开，体力约束 | AN_.../SYS_02 |

- 动作动词尽量少而可组合（3A 设计原则：少动词、多情境）。
- 明确**按住 vs 点按 vs 双击**的使用规则：高风险动作（开机关、丢弃）用按住；常用低风险用点按。全游戏统一。

### 2. 交互矩阵（核心派工依据）

行=可交互对象类型，列=动词，格内写交互结果与所需反馈。

| 对象 \ 动词 | 看/观察 | 使用 | 推 | 躲藏 | 拾取 |
|---|---|---|---|---|---|
| 门 | 显示状态 | 开（1.2s 按住） | 仅可推动的 | 否 | 否 |
| 柜子 | 内有物品提示 | 打开 | 否 | 进入躲藏 | 否 |
| 尸体 | 观察特写 | 搜身 | 否 | 否 | 概率物品 |

矩阵必须覆盖：每类对象至少 1 个动词；玩家会本能尝试的动作（对门按攻击、对窗户跳）都要有合理反馈，不能「按了没反应」。

### 3. 上下文交互（Contextual Action）

- 交互入口统一到一个主交互键，对象决定动作（靠近柜子变「躲藏」，靠近门变「开门」）；UI 提示图标随平台（键鼠/手柄）切换。
- 同时存在多个交互目标时的优先级规则（最近+视线中心），并给最大交互角度/距离（如 30°、2.5m）。
- 交互反馈三层，缺一不可：**确认层**（按键立即：图标变化+音效）→ **过程层**（进度环/动画）→ **结果层**（对象状态改变+音效+可能的手柄震动）。

### 4. 操作映射规则

- 键鼠与手柄双方案，所有按键可重映射（Steam 上架与可访问性硬要求）；手柄以 Xbox 布局为基准，PS 图标跟随平台。
- 冲突解决表：同一动作在不同上下文（步行/瞄准/过场/UI）的映射。
- 灵敏度：视角 X/Y 独立调节、反转、摇杆死区（默认 5-10%）、加速度曲线。
- 操作延迟预算：按键到画面响应 ≤100ms（动作/逃生类争取 ≤60ms），逐动作核对动画前摇是否吞噬响应。

### 5. 游戏手感（Juice）清单

跨系统统一，详见 04 第 7 节；本篇负责落地：每次交互的音效、粒子、镜头、震动、UI 动效规格。原则：**每个操作 100ms 内必有视听触反馈**；失败操作也要有反馈（门锁了→把手晃一下+金属声+角色微摇头）。

### 6. 教学引导

- 无弹窗原则：环境示范→安全试错→实战（与 03 关卡 beat 对齐）。
- 控制提示在首次需要时出现，已掌握的提示不再出现；提供「教学日志」供回看。

## 二、UI / UX

### 7. UI 资产总表

逐个列出：编号、界面名、触发方式、是否暂停游戏、元素构成、引用素材状态。

- HUD（血量/体力/交互提示/目标指引/小地图等）
- 菜单：主菜单、设置（画面/声音/控制/游戏性/可访问性分页）、暂停、存档读档、图鉴/文档、地图、背包
- 过场 UI：字幕、对话选项、QTE
- 系统 UI：商店、升级、制作（如有）

### 8. HUD 设计原则

- 恐怖/沉浸类：默认隐藏一切，仅在变化时短暂浮现（受击红屏、低体力音效+边缘提示）；交互提示只在可用时出现。
- 信息层级：持续需要的常驻、偶尔需要的呼出、危险时的强提示；用一张标注安全区的线框图（1920×1080 与 21:9 超宽适配）。
- 安全区：核心信息距屏幕边 ≥5%（主机/电视安全区），HUD 元素在 16:9 与 21:9 下不错位。

### 9. 菜单流程（每个菜单画 Mermaid 状态图）

- 主菜单首次进入 ≤3 次操作到「开始游戏」；继续游戏永远是第一项。
- 设置项清单逐项列（分辨率/全屏/垂直同步/帧率上限/DLSS-FSR-XeSS/FOV/运动模糊/胶片颗粒/色差/音量四总线/字幕开关/字号/色盲模式/按键重映射/难度）。
- 存档：自动/手动槽位、存档时间截图、存档损坏提示与回退。

### 10. UI 视觉与动效规范

- 字体：标题/正文中文字体授权确认（授权范围含游戏发行），正文 HUD 字号 ≥18px@1080p，字幕 ≥28px；西文配套字体。
- 图标：按键图标四套（键鼠/Xbox/PS/Steam Deck）；状态图标线性统一风格（遵循美术圣经 02）。
- 动效：UI 切换时长 150-250ms（缓动曲线标注），按钮四态（正常/悬停/按下/禁用）都有声画反馈。
- 文本不烘焙进贴图（本地化硬要求）。

### 11. 本地化与可访问性 UI

- 语言：至少简中/繁中/英文首发；字符串外置；英文→德/俄文本膨胀 30-50% 的界面留白与自适应规则。
- 字幕：开/关、字号三档、说话人标注、背景透明度、字幕不遮挡关键画面（底部安全区）。
- 可访问性：色盲三模式（色弱友好配色，不依赖颜色单一编码）、QTE 可改长按/自动、瞄准辅助、完全手柄支持、键鼠全功能、按键重映射、闪烁内容 <3Hz 或警告、难度/战斗强度选项、字幕+可视化音效（听觉信息用方向指示）。

## 完成定义

- [ ] 动词表穷举且键鼠/手柄双映射，全按键可重映射
- [ ] 交互矩阵覆盖全部对象类型，本能尝试无「无反应」死角
- [ ] 上下文交互优先级、角度距离、三层反馈明确
- [ ] 操作延迟逐动作 ≤100ms 并有核对方法
- [ ] UI 总表无遗漏；每个菜单有状态图；3 次操作内可继续游戏
- [ ] HUD 有安全区/超宽屏适配线框
- [ ] 字体授权确认、字号达标、四套按键图标
- [ ] 本地化与可访问性清单逐项落实（Deck 验证需要完整手柄支持）
