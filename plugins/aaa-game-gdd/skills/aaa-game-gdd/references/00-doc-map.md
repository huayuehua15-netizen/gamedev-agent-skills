# 00 文档体系总览

## 解决什么问题

3A 游戏不是「一份 GDD」，而是一套分层文档群：上层定方向（愿景、美术、技术预算），中层定系统（玩法、交互、叙事），下层定每一个可派工的资产（场景/角色/道具/动画/对话单页）。本篇给出文档树、各文档的读者/阶段/输入输出，以及规模裁剪规则。

## 标准 GDD 目录结构

```text
<游戏名>_GDD/
├── README.md                 # 文档首页：文档索引、当前版本、阅读顺序
├── 01-愿景与Pitch.md          # 一句话讲清游戏、核心支柱、对标、卖点
├── 02-美术圣经.md             # 全局视觉风格、色彩、材质、形状语言、禁忌
├── 03-场景与关卡.md           # 世界总图 + 场景/关卡索引表（单页放子目录）
├── 04-玩法系统.md             # 核心循环 + 系统清单 + 数值总表（单系统放子目录）
├── 05-剧情与台词.md           # 故事大纲、章节结构、叙事规则 + 对话索引
├── 06-交互与UIUX.md           # 操作映射、交互矩阵、手感、HUD、菜单、可访问性
├── 07-角色规格.md             # 角色总表 + 角色索引（单页放子目录）
├── 08-物品建模规格.md         # 全局建模/贴图/LOD/命名规范 + 道具索引
├── 09-动画规格.md             # 全局动画规范、状态机规则 + 动画索引
├── 10-音频设计.md             # 音乐/音效/配音规划、总线、响度标准
├── 11-技术与性能.md           # 引擎、渲染管线、全平台预算、工具链
├── 12-质量与Steam验收.md      # 阶段门禁、QA、Steam 上架、3A 十维评分
├── scenes/        # 每个场景一张 scene-sheet：SC_01_废弃医院.md
├── levels/        # 每个关卡一张 level-sheet：LV_01_序章逃亡.md
├── characters/    # 主角/敌人/NPC：CH_Player_凛.md、EN_01_缝合者.md
├── props/         # 道具/武器/环境资产：PR_01_生锈钥匙.md、WP_01_消防斧.md
├── animations/    # 每条动画一张 animation-sheet：AN_Player_HeavyAttack_01.md
├── dialogue/      # 每段对话/过场：DL_01_序章_医生独白.md
└── systems/       # 每个玩法系统一张 system-sheet：SYS_战斗.md、SYS_背包.md
```

## 文档矩阵（谁读、何时写、输入/输出）

| 文档 | 主要读者 | 起步阶段 | 输入 | 输出可派工内容 |
|---|---|---|---|---|
| 01 愿景 | 全员/发行 | 概念 | 想法、对标作品 | 核心支柱、范围边界、卖点 |
| 02 美术圣经 | 美术/TA | 概念末 | 01、参考图收集 | 风格规则、色板、材质语言、概念图方向 |
| 03 场景关卡 | 关卡/美术/音频 | 垂直切片 | 01/02/04/05 | 场景搭建单、动线、遭遇表、环境资产清单 |
| 04 玩法系统 | 策划/程序 | 概念 | 01 | 系统规格、数值表、状态机、存档字段 |
| 05 剧情台词 | 编剧/音频/动画 | 垂直切片 | 01/07 |  beat 表、台词脚本、配音单、过场需求 |
| 06 交互 UI | 策划/UI/程序 | 垂直切片 | 04/07 | 按键映射、交互矩阵、UI 清单、反馈规格 |
| 07 角色 | 美术/动画/AI 程序 | 垂直切片 | 01/04/05 | 建模单、动作清单、行为树、数值 |
| 08 建模规格 | 美术/TA | 垂直切片 | 02/11 | 统一技术规范 + 每个道具的需求单 |
| 09 动画规格 | 动画/程序 | 垂直切片 | 06/07/04 | 动作清单、状态机、时长帧率、事件埋点 |
| 10 音频 | 音频 | 垂直切片 | 03/05/06 | 音频资产清单、触发矩阵、总线规格 |
| 11 技术性能 | 程序/TA | 概念末 | 01 | 引擎选型、预算表、工具链、平台目标 |
| 12 验收 | 全员/QA | 全程维护 | 全部文档 | 门禁、测试矩阵、上架清单、评分表 |

## 规模裁剪规则（小团队也能用）

- **单人/2-3 人团队**：01、02、04、06、08、09、11、12 必须写全；03/05/07/10 的核心文档可压缩到 1-2 页，但**资产单页不能省**（单页是派工和验收的最小单位）。
- **垂直切片前**只写 01、04 骨架、11 预算；不要提前写全 100 个道具的单页，样板单页每类做 1 个验证流程。
- **一条反例**：把所有内容写进一个 5 万字 GDD 大文件 → 没人维护、无法派工、必然腐烂。核心文档放规则与索引，实例放单页。

## 文档之间的引用与编号

- 所有编号全局唯一：场景 `SC_##`、关卡 `LV_##`、角色 `CH_/EN_/NPC_`、道具 `PR_/WP_`、动画 `AN_`、对话 `DL_`、系统 `SYS_`、音频 `AU_`、UI `UI_`。
- 引用时写编号+名称，如「场景 `SC_03_废弃医院` 中使用武器 `WP_01_消防斧`」。
- 每份核心文档维护一张索引表（编号/名称/状态/负责人/对应单页链接）。
- 状态流转：`草稿 → 评审中 → 已锁定 → 已实现 → 已验收`。锁定后改动必须升版本号。

## 完成定义（本篇）

- [ ] README 索引表列出全部文档且链接可跳转
- [ ] 每份文档有编号、版本、状态、负责人、更新日期
- [ ] 每个要做的资产/系统都有对应单页，无「口头需求」
- [ ] 编号规则全局一致，交叉引用无悬空编号
- [ ] 每个文档状态可查，锁定文档有变更记录
