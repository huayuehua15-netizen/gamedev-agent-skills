# 11 技术架构与性能预算

## 解决什么问题

在做第一套资产之前锁定引擎、管线与全平台性能预算，避免量产后「面数超了、内存爆了、Deck 跑不动」的全面返工。本文档是美术/动画预算的总依据，08/09 中的数字必须与本表一致。

## 何时写

概念末期第一版，垂直切片结束时锁定（此时已有真实可测数据），之后只允许小幅调整。

## 1. 引擎与版本锁定

- 引擎/版本/渲染管线（Unity 6（6000.x LTS）+ URP，与 `unity-gameplay-dev` 的默认技术栈保持一致；Unreal 5+ Deferred/Forward + Lumen/Nanite 决策；Godot 4+ Forward+/Mobile）写死版本号，全员统一，升级走专项。
- 选型决策表：目标平台、画质档位、团队熟悉度、Nanite/虚拟贴图/烘焙 GI 方案、是否需要前向渲染（移动端/Deck）。
- 第三方依赖清单（插件/中间件/SDK）：版本、授权、维护状态、平台支持。

## 2. 目标平台与规格（逐档列表，给出项目实际目标）

| 档位 | 分辨率 | 帧率 | 帧时间 | 画质档位 |
|---|---|---|---|---|
| 推荐 PC | 1080p/1440p/4K | 60fps（可解锁） | 16.6ms | 高 |
| 最低 PC | 1080p | 30fps 稳定 | 33.3ms | 低 |
| Steam Deck | 1280×800（唯一原生分辨率） | 30fps 锁（目标可 60） | 33.3ms | Deck 专用档 |
| 主机（若有） | 按平台 TRC | 30/60 模式 | — | — |

## 3. 帧时间预算（60fps = 16.6ms 为硬上限）

示例分配（项目首测后用 profiler 实测替换）：

| 模块 | PC 预算 | Deck 预算 |
|---|---|---|
| CPU 游戏逻辑/AI | 2.0ms | 4.0ms |
| CPU 渲染（剔除/合批/绘制提交） | 2.5ms | 5.0ms |
| GPU 不透明几何（GBuffer/前向） | 3.0ms | 6.0ms |
| 透明/特效/后处理 | 2.5ms | 5.0ms |
| 光照/阴影 | 3.0ms | 5.0ms |
| 音频/IO/其他 | 0.8ms | 2.0ms |
| 余量 | 2.8ms | 6.3ms |

规则：垂直切片必须实测 profiler 数据；任何系统超预算先报预算再优化，不允许「先做了再说」。

## 4. 几何与 Draw Call 预算

- 每帧可见三角面、Draw Call/Batch 上限按**项目体量档位**给。同一套数字不能同时服务 3A 和独立团队——按下面三档各写一行，并对齐本项目实际场景：

| 档位 | 可见三角面/帧 | Draw Call | 说明 |
|---|---|---|---|
| 独立 / 小团队（推荐起点） | 20-80 万 | 300-800 | 绝大多数单机项目的真实区间；先按这个做，再按实测放宽 |
| 中型（10-30 人） | 80-250 万 | 800-2000 | 需要 LOD + 合批 + 遮挡剔除全部到位 |
| 3A 级 | 250-500 万 | 2000-5000 | 基准测试级数字，不是默认目标；需要 Nanite/虚拟贴图或重度 HLOD 支撑 |

  Deck/最低档在此基础上下调到约 1/4，并用 profiler 实测确认。**没有实测数据时，从"独立"档起步**——预算宁低勿高，超了才发现要重做资产是最贵的事。
- 同屏角色数、同屏动态灯光数、阴影级联数、粒子数上限（按档位写具体数字）。
- 复用与合批：模块化图集、GPU Instancing（草/杂物）、遮挡剔除（HLOD/OC 数据）、视距/LOD 距离表。

## 5. 贴图与内存预算

| 类别 | 规范 |
|---|---|
| 常驻内存上限 | PC 12-16GB 设备可用预算内；Deck 为 16GB LPDDR5 共享内存，游戏实际可用约 8-10GB（其余留给 SteamOS/合成器），给具体值 |
| 贴图池 | 各档纹理预算（如 PC 4GB / Deck 1.5GB 显存），按场景流式加载 |
| 压缩格式 | PC：BCn；Deck/移动端：ASTC，给质量档位 |
| 流式 | 场景纹理/几何按区流式，Mipmap 常驻策略 |
| 音频内存 | 见 10，常驻 100-200MB 量级（按项目） |

## 6. 包体与加载

- 包体目标（如首包 ≤20GB / 全量 ≤60GB，按品类定）；高重复资产、未压缩音频/WAV 是膨胀主因，列减包清单。
- 加载：冷启动到主菜单时长（SSD 上现代 PC 参考 ≤15s，争取 ≤8s；上机械盘或首包解压时可放宽到 ≤30s）；场景切换 ≤10s（争取 ≤5s）；过程中流式不卡顿（帧时间尖峰 ≤2 帧）。
- 加载画面与剧情提示结合；Steam 预下载/着色器预缓存（vulkan shader cache）利用。

## 7. 存档与数据

- 存档方案：本地存档 + Steam Cloud（路径、槽位数、自动存档触发）。
- 存档字段由各系统单页汇总；**版本兼容**：老存档读入新版本的迁移规则，每个版本写迁移函数；新增字段有默认值。
- 存档损坏保护：写入用临时文件+原子替换、保留最近 3 个备份。
- 数据驱动：数值/台词/UI 文本全部外部化（表/JSON/本地化表），禁止硬编码。

## 8. 输入与平台兼容

- 输入系统抽象：键鼠、Xbox、PS、Steam Deck 手柄、Steam Input；重映射方案（与 06 对齐）。
- Deck 验证四大项（见 12）：输入、显示（默认分辨率/文字可读）、无缝（控制器/触屏）、系统支持（Proton/音频/挂起恢复）。
- 超宽屏（21:9/32:9）、多显示器、HDR（若做）、全屏/窗口模式、DLSS/FSR/XeSS 档位、帧率上限。

## 9. 工具链与版本管理

- 资产管线：Blender/Maya 版本、Photoshop/Substance 版本、统一导出脚本；命名与目录规范引用 08。
- 版本控制：Git + LFS（或 Perforce），二进制资产走 LFS；分支策略、评审、提交规范。
- 工程规范：场景/预制体结构、谁能改全局设置、prefab 与场景拆分避免冲突。
- 构建/CI：每日自动构建、自动跑冒烟、崩溃上报（如 Sentry/Backtrace 类）、版本号与渠道包。

## 10. 质量与性能流程

- 性能是功能：每个里程碑跑一次全平台 profiler 并归档；固定测试场景（重资产场景）。
- 性能预算表维护人（TA/主程）；超预算资产不予验收（与 08/09 DoD 联动）。
- 崩溃率目标：上架前崩溃率 <0.1% 会话（或写明确目标），零必现崩溃。
