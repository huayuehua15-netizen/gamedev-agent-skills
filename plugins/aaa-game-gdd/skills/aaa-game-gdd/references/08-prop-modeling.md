# 08 物品 / 道具建模规格

## 解决什么问题

统一全部道具、武器、环境资产的技术规格与交付流程，让美术外包或新成员只读一张 prop-sheet 就能产出可直接进引擎、无需返工的合格资产。本篇先给全局硬规范（每个 prop-sheet 都引用），单页只写该资产的个体需求。

## 何时写

垂直切片期：本文档锁定 + 3 个不同类型样板资产（手持道具/场景道具/武器）。量产期：每资产先有单页再开工。

## 一、资产管线（每个资产必须走完）

```
需求单(prop-sheet) → 概念/参考确认 → 白模(blockout) → 高模(high poly)
→ 低模拓扑(low poly) → UV(贴图UV + 光照UV) → 烘焙(法线/AO/Curvature)
→ PBR材质贴图 → LOD ×N → 碰撞体 → 引擎导入设置 → 挂点与交互测试 → 验收
```

每一步都有验收点，禁止跳步。白模先过比例/剪影/占屏关系，再做高模。

## 二、全局硬规范（预算与引擎/平台对齐，见 11）

### 1. 面数预算（三角面，行业参考值，按项目预算调整）

| 资产类别 | LOD0 | LOD1 | LOD2 |
|---|---|---|---|
| 手持道具（钥匙/手电/小物） | 1k-3k | 500 | 150 |
| 常规场景道具（椅子/柜子/器械） | 2k-8k | 1k-3k | 300-800 |
| 大件场景资产（床/车/大型设备） | 8k-20k | 3k-8k | 800-2k |
| 第一人称武器（近景） | 15k-40k | 5k-10k | 1.5k |
| 模块化建筑件（墙/地板/门） | 单件 0.5k-3k | — | 视距离 |

- 屏幕占比决定预算：只在桌面出现的小物与挡路的大件不同档；同屏实例数量 ≥20 的资产预算下调 30-50%。
- 预算超支必须在单页说明理由并经 TA 批准。

### 2. 贴图与材质

- PBR 金属/粗糙度工作流；贴图尺寸：手持/近景 2048²；普通道具 1024²；复用模块化件用图集（atlas）。
- 通道打包（与 11 一致，常见两种）：
  - RMA 式：R=AO、G=Roughness、B=Metallic；或 ORM：R=AO、G=Roughness、B=Metallic；法线用 DirectX OpenGL 按引擎规定（Unity 默认 OpenGL 绿通道向上，Unreal 相反）。
- 通用粗糙度/金属度参考：金属裸露 0.2-0.6 粗糙度、锈蚀 0.7-0.9；木材 0.5-0.8；积灰表面整体粗糙度 +0.1；湿区降低粗糙度并加深 albedo。
- UV：统一 0-1 空间、最小缝隙 ≥4px@对应分辨率、相同 texel density（统一 1024px/m，主角与近景可 2048px/m）；共用材质的模块件必须对齐世界网格。
- 第二套 UV（UV2/lightmap UV）：静态场景资产必须提供，不重叠、留边。
- 禁止：纯色贴图（必须有明度变化/噪点/污渍）、未利用的大面积透明空白、法线贴图当细节用却不做顶点色。

### 3. LOD

- 全部资产 ≥3 级 LOD；切换阈值按屏幕占比写（如 LOD1 <50%、LOD2 <25%，具体在引擎内定）。
- LOD 做法：减面、合并材质 ID、去除小部件；远处用十字片/impostor。LOD 切换不得可见跳变（屏幕测试）。

### 4. 碰撞体（最常被漏）

- 每个可放置资产提供简化碰撞：用胶囊/盒/凸包，命名 `UCX_资产名_01`；禁止直接拿渲染网格做碰撞。
- 可交互物：门/抽屉的碰撞体必须按可动部件拆分并设枢轴；地面资产无针状/镂空导致卡住的碰撞。
- 不需要碰撞的纯装饰小物（落叶/碎屑）标记不碰撞。

### 5. 骨骼与挂点（手持/可动资产）

- 武器：手持骨骼挂点 `GripPoint`、特效挂点 `MuzzlePoint`、拖尾挂点；可开合物（门/柜）枢轴位置与旋转轴。
- 第一人称武器：双臂模型与相机的相对关系、FOV 位置、穿模检查。

### 6. 命名规范（全项目统一，禁止中文与空格）

- 网格 `SM_类别_名称_序号`（SM_Prop_HospitalWheelchair_01）；骨骼网格 `SK_`；贴图 `T_名称_类型_分辨率`（T_Wheelchair_BC_1024 / _N / _RMA）；材质 `M_`；材质实例 `MI_`；纹理类别后缀：`BC`(Albedo)、`N`(Normal)、`R`(Roughness)、`M`(Metallic)、`AO`、`E`(Emissive)、`RMA`。
- 模块化建筑件按尺寸：`SM_Wall_400x300_A`、`SM_Floor_400x400`，全部对齐世界网格（边长 1m/2m/4m 体系）。
- 引擎内文件夹：`Art/Props/区域/资产名/`，源文件与导出文件分开。

### 7. 导出与引擎设置

- 交换格式：FBX（Unity）或 FBX/glTF（Unreal）；统一单位（厘米/米按引擎）、缩放因子 1、前向/上向轴按引擎（Unity -Z forward、Y up）。
- 导入设置逐项写进单页：静态/动态、生成 Lightmap UV 或自带、材质槽数量、压缩设置（移动端/PC 纹理压缩格式）、Read/Write 关闭、mipmap 开启。
- 静态资产合批/GPU Instancing 标记；同场景材质槽尽量合并。

## 三、prop-sheet 单页内容

1. 基本信息：编号、名称、类别、首次出现场景（引用 SC）、数量与复用范围、是否可交互/可拾取、近景还是远景、第一人称还是第三人称。
2. 需求描述：用途、玩家会对它做什么（看/拿/砸/打开/推动），它在叙事中暗示什么（引用场景叙事道具清单）。
3. 参考图：真实照片/影视/其他游戏参考，标注学什么。
4. 概念图需求：角度、关键细节、做旧程度。
5. 尺寸：真实尺寸（cm）、是否夸张比例（如恐怖道具压迫感）。
6. 技术规格（引用全局表，逐项确认本资产取值）：面数预算、贴图尺寸、材质 ID 数、LOD、碰撞、挂点、是否静态、是否需要 lightmap。
7. 交互/动画/特效需求：开门动画、破碎类型、挂点特效、音效（引用 10）。
8. 验收清单（见下）。

## 四、资产完成定义（DoD）

- [ ] 白模比例/剪影/占屏通过关卡与美术评审
- [ ] LOD0 面数在预算内，拓扑四边面为主、无多余边、硬边/光滑组正确
- [ ] 两套 UV 合格，texel density 统一，烘焙无明显接缝/瑕疵
- [ ] PBR 贴图齐全且命名/分辨率/通道打包符合规范，金属度为 0 或 1 为主（无滥用灰值）
- [ ] 三级 LOD 齐全且切换无跳变
- [ ] 简化碰撞体 `UCX_` 正确，可动部件枢轴正确
- [ ] 命名、目录、导入设置、单位、轴向全部符合规范
- [ ] 引擎内无穿模/悬浮；实例化摆放性能测试通过
- [ ] 交互反馈（音效/动画/特效）已挂载
- [ ] 源文件（高模/工程）与导出文件均归档
