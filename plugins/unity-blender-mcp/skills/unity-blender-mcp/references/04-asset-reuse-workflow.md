# 素材复用 9 步工作流

> 每要一个资产，严格走完这 9 步。目标：素材进 Unity 后开箱即用，不返工、不侵权、不炸性能。

## 步骤 1：下需求单（30 秒，防止找错）

明确并记录：
- 资产名、用途、数量（单件还是一套）
- 近景可交互 / 中景 / 远景背景（决定面数预算）
- 美术风格（写实/低模/卡通）与目标尺寸（米，如椅子 0.9m 高、门 2.0m）
- 是否需要骨骼/动画、碰撞、破碎、可开启部件
- 授权要求（商业项目：CC0 或可商用授权）

## 步骤 2：按优先级搜索

顺序见 03 节"选型优先级"：MCP 内置 → CC0 站 → 聚合库 → 市场免费区 → 国内库 → AI 生成 → 自建。
- 每个需求至少看 3-5 个候选，不要见第一个就下。
- 整批资产优先选同一素材包，保证风格、贴图、比例统一。

## 步骤 3：候选评估（决定下哪个，甚至要不要放弃）

对候选逐项打分（可在心里过）：
- [ ] 授权是否满足（NC/存疑直接淘汰）
- [ ] 面数是否在预算内（超过预算但结构好可减面；虚高扫描件减面代价大）
- [ ] 拓扑：是否四边面为主、无明显烂面、可编辑
- [ ] 有 UV、贴图完整（BC/N/RMA 齐全度与分辨率）
- [ ] 有骨骼/动画需求时是否已绑定、动作是否够用
- [ ] 风格是否与项目一致，能否用材质/缩放调整
- [ ] 格式是否可用（FBX/OBJ/glTF/Blend；`.max` 有可用 FBX 版才考虑）

**淘汰标准**：授权存疑、或拓扑/贴图修复比重做还慢、或面数超标且细节无价值——立刻换下一个，别在烂素材上耗。

## 步骤 4：下载到暂存区

- 统一暂存目录：Unity 项目内 `Assets/Imports/<资产名>/`（引擎外先放 `_inbox/`，清洗后再进）。
- 保存授权页面截图/链接到该目录；非 CC0 立即登记台账。
- 下载原件**只读保留**，不在原件上改。

## 步骤 5：Blender 审计（跑脚本，用数据决策）

- 打开独立 Blender 场景导入，执行 `scripts/blender_asset_audit.py`（MCP 粘贴或命令行）。
- 报告字段：对象清单、网格三角面数、材质数、UV 层、贴图路径与色彩空间、变换是否归零、是否含骨骼/动画及动作数、尺寸（米）。
- 对照预算（与 GDD 一致）：

| 类别 | 三角面预算（可参考） |
|---|---|
| 手持/小道具 | 1k-3k |
| 常规场景道具 | 2k-8k |
| 大件家具/设备 | 8k-20k |
| 第一人称武器 | 15k-40k |
| NPC | 15k-40k |
| 敌人 | 40k-80k |
| 主角 | 60k-100k |
| LOD 三级 | 100% / 50% / 25% |

## 步骤 6：清洗标准化（Blender）

按需执行（片段见 01，脚本见 `blender_prep_unity.py`）：
- 删除多余对象（摄像机、灯光、占位、隐藏垃圾、空组）
- 应用旋转与缩放；原点归位（道具几何中心/角色脚底）
- 重算法线、删松散点、合并重复点；必要时重拓扑/减面
- 生成 LOD 副本（近景资产需要时）
- 材质转 Principled BSDF；贴图按规范命名、色彩空间改对（颜色 sRGB、数据贴图 Non-Color）
- 文件名/对象名/材质名全转英文规范命名
- 角色：统一骨架命名（或 Mixamo 骨骼），确认 T-pose/朝向

## 步骤 7：导出 Unity FBX（脚本固化参数）

- 静态：`blender_prep_unity.py`，`bake_anim=False`。
- 角色/带动画：`bake_anim=True`，`add_leaf_bones=False`；动作可逐段单独导出（命名 `SK_名@Idle.fbx` 约定）。
- 贴图与 FBX 一起进 `Assets/Imports/<资产名>/`，确保无外链丢失（路径全英文）。

## 步骤 8：Blender 质检渲染（出品质图，眼睛验收）

审计报告只证明数据没坏，造型、贴图、金属/粗糙度、法线是否正确要靠眼睛。导出后立刻跑：

```powershell
# 无 HDRI（内置三点布光，任何环境可跑）
blender --background --python scripts/blender_asset_qa_render.py -- "SM_xxx.fbx" "qa_xxx.png" --res 1920x1080
# 有 HDRI（摄影棚质感，HDRI 从 Poly Haven 下载，步骤 2 同库）
blender --background --python scripts/blender_asset_qa_render.py -- "SM_xxx.fbx" "qa_xxx.png" --hdri "studio_small_03.hdr" --turntable 3
```

脚本自动按包围盒取景（宽/高双向约束，不会裁掉顶部）、落地、AgX 色彩、中性背景。MCP 里全文粘贴则渲染当前场景。目检要点：造型无破损/穿插、贴图方向正确（字不反、木纹不糊）、法线无凹凸颠倒、金属该亮的亮布料该哑的哑。不过眼就回步骤 3/6，不带病进 Unity。

## 步骤 9：Unity 导入验收（对照 DoD 逐项勾）

1. `refresh_unity`，确认 `AssetPostprocessor` 已处理（无报错）。
2. 比例与朝向：拖进验收场景，人物约 1.7m、与参照物比例真实、不躺倒。
3. 材质：无粉色、颜色/法线/粗糙度正确、贴图无丢失。
4. 碰撞：静态道具可被射线/角色阻挡；角色有胶囊体。
5. 角色：Humanoid Avatar 映射正确，播放 Idle 无 T-pose，移动不脚滑。
6. 静态/光照：需要烘焙的静态物体有第二套 UV（Lightmap UV，无则勾选导入器或在 Blender 生成）。
7. 生成 Prefab 到正式目录，移除暂存场景临时件。
8. `read_console` 零报错；截关键视角图交付用户确认。

## 验收清单（直接贴进交付）

- [ ] 授权登记完成（CC0 记来源；CC-BY 列署名；无 NC/存疑件）
- [ ] 审计报告在预算内，UV/法线/变换合格
- [ ] 质检渲染图目检通过（造型/贴图/法线/金属粗糙度）
- [ ] 比例、朝向、材质、碰撞、动画全部正确
- [ ] Prefab + LOD 就位，控制台零报错
- [ ] 交付截图 + 台账已更新
